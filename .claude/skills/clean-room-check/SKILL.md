# Clean-room check

Pairs with the `clean-room-compliance` agent.

## What is allowed
Facts (numbers, colours, sizes, spacing, timings, easings, text content), observed behaviour (what happens on click, hover, scroll and keyboard), and asset files (photos, icon and logo artwork used as assets).

## What is not allowed
The reference's markup structure, CSS rules, class names or JavaScript logic, whether copied, renamed, paraphrased or ported line by line.

## Procedure
1. Data hygiene: `design/capture/` and `design/spec/` must hold values only (text, computed styles, boxes, image URLs). No HTML files, DOM dumps or bundles anywhere in the repo.
2. Tokens: every value in `design/tokens.md` and `styles/tokens/*.css` traces to a measurement, not to copied CSS.
3. Icons: `components/icon-art.generated.ts` is generated by `scripts/spec/build-icon-registry.mjs` from `design/spec/icons.json` (viewBox, paint and shape geometry only) and rendered through `components/ArtIcon.tsx`. It is asset data; no class names or wrapper markup come with it.
4. Components: read the JSX trees and confirm they use our own semantic structure and names. Search for reference-style class names or copied handler logic.
5. Report anything doubtful with the file and what to rewrite; do not silently rewrite.

## Output
A short provenance note: what was checked, what was found, what (if anything) needs a rewrite.
